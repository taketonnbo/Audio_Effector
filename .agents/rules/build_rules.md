# ビルド・検証ルール (Build Rules)

エージェントがコードの構文チェック、コンパイル確認、テスト検証のために `dotnet build` を実行する際は、**ユーザーがエディタ上でアプリをデバッグ実行中であってもセッションを強制終了・ファイルロック競合させない** よう、以下の規則を厳守してください。

## 1. 隔離ビルド（-p:OutDir の使用）
- 通常の `dotnet build` はデフォルトで `bin\Debug\` 配下のファイルを上書きしようとするため、デバッグ実行中のプロセスロック（`MSB3026`）やデバッグ中断を引き起こします。
- エージェントがビルド検証を行う際は、**必ず専用の一時出力先ディレクトリ（`.agent_build/`）を指定** してください。
- コマンド例:
  ```powershell
  dotnet build AudioEffector.sln -p:OutDir="$(Get-Location)\.agent_build\"
  ```

## 2. 一時ディレクトリのクリーンアップ
- ビルド検証が完了した後は、作業ディレクトリをクリーンに保つため、`.agent_build` ディレクトリを削除してください。
- コマンド例:
  ```powershell
  Remove-Item -Recurse -Force -Path '.agent_build' -ErrorAction SilentlyContinue
  ```

## 3. テスト実行時の配慮
- `dotnet test` を実行する際も、ビルド成果物の競合を避けるため、同様に出力ディレクトリや `--no-build` オプションを適切に組み合わせて実行してください。

## 4. 非同期処理・テスト・ビルド実行時の待機とタイマー管理（待ちぼうけ防止）
ビルドやテスト実行が長時間終わらない、または待機処理が異常終了した際に、エージェントが無制限に放置・待機（待ちぼうけ）状態になるのを防ぐため、以下の規則を厳守してください。

- **タイムアウト監視とタイマー設定**:
  - コマンドがバックグラウンドタスクとなった場合、漫然と無限待機してはならない。
  - 必要に応じて `schedule` ツールでワンショットタイマー（ビルド時は60秒、テスト時は120秒等）を設定するか、定期的に `manage_task(status)` でタスクの進行ログ（`Last progress`）を監視する。
- **滞留時の速やかな中断（Kill）と原因調査**:
  - タスクのログ出力が一定時間（例: 30〜60秒）停止している、または想定時間を超過した場合は、直ちに `manage_task(kill)` でプロセスを終了させる。
  - テストがハングする主因（STAスレッド制約、オーディオドライバやハードウェア初期化、無限待機ループ等）を特定し、スタブ/モック化やフィルタ実行（`--filter`）に切り替える。
- **異常終了時の即時リカバリ**:
  - タスクがエラー終了した場合は即座にタスクログを精査し、放置せずに速やかに原因分析・是正措置（再ビルド、設定見直し等）を実施する。
