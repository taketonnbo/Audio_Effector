# UI仕様書作成ルール (UI Specification Rules)

本ドキュメントは、Audio Effectorにおける各画面・ビュー・UIコンポーネントの仕様書（UI仕様書）を作成する際に、全エージェントおよび開発者が遵守すべき必須ルールを定めたものです。
[デザインシステム（設計/デザインシステム/）](../../設計/デザインシステム/index.md) の内容を完全に継承し、視覚的一貫性、操作のアフォーダンス、および描画パフォーマンスを担保することを目的とします。

---

## 1. ドキュメント配置とファイル命名規則

1. **配置ディレクトリ**:
   - `設計/画面設計/<機能名・画面名>/` 配下に作成します。
   - 例: `設計/画面設計/全曲一覧/`, `設計/画面設計/歌詞パネル/`
2. **仕様書ファイル名**:
   - 必ず日本語で `<機能名・画面名>UI仕様書.md` とします。
   - 例: `全曲一覧UI仕様書.md`, `歌詞パネルUI仕様書.md`
3. **モックアップとリンク構成**:
   - 仕様書内には大まかな部品配置・構造を定義する「ASCIIベースのモックアップ」を記載します。
   - 後続のFigma作成タスクで作成されるデザインファイルへの参照として「Figmaリンク」項目を設置します。

---

## 2. 必須セクション構成

作成するUI仕様書は、必ず以下の構成を含めてください：

```markdown
# <画面・コンポーネント名> UI仕様書

## 1. 概要 (Overview)
- 画面の目的、ユーザー体験、主要な操作対象オブジェクト（Track, Album等）の明示。

## 2. 実装イメージ（モックアップ）
### 2.1 ASCIIモックアップ
- 主要オブジェクト仕様に準拠した画面配置・レイアウトを表現するテキストアート（コードブロック）。

### 2.2 Figmaモックアップ
- Figmaデザインへのリンク（別タスクにて作成予定のプレースホルダー）。

## 3. 画面配置とペインレイアウト
- 全体レイアウト（全体レイアウト・ペイン構成UI仕様書）における位置付け（左サイドバー、中央ワークスペース、右パネル等）。
- グリッド構造（RowDefinitions / ColumnDefinitions）やサイズ（Width, Height, MinWidth）。

## 4. デザイントークンの適用
- 使用するカラートークン（背景・前景・アクセント・ボーダー）。
- タイポグラフィ（FontSize, FontWeight）、角丸（CornerRadius）、スペーシング（Margin, Padding）。
- 実色カラー見本（プレビューチップ）付きの対応テーブル。

## 5. 構成要素と共通コントロール
- 使用する共通コントロール（PrimaryButton, SearchBox, NeonSlider, VirtualizedListBox等）。
- オブジェクトの各状態スタイル（Normal, Hover, Pressed, Selected, Disabled, Active）。

## 6. アニメーションとインタラクション
- クリック、ダブルクリック、右クリック（コンテキストメニュー）、ドラッグ＆ドロップ（D&D）。
- 表示・非表示時のスライドアニメーション、展開・折りたたみ動作。

## 7. パフォーマンス最適化要件
- UI仮想化の指定、Visibility="Collapsed" 連動、高負荷エフェクトの排除確認。

## 8. 関連Issue・仕様書
- 親Issue、関連ユースケース、関連主要オブジェクト仕様書へのリンク。
```

## 3. デザインシステム遵守ルール

各UI仕様書を作成する際は、以下のデザインシステム仕様書を必ず確認し、その定義を厳格に適用してください：

### 3.1 デザイントークンの適用 (`01_デザイントークン仕様書.md`)
- **任意カラーコードの直書き禁止**:
  - UI仕様書内で色を指定する際は、必ず定義済みのデザイントークン名（`WindowBackgroundBrush`, `PanelBackgroundBrush`, `NeonCyanBrush`, `BorderBrush`, `TextForegroundBrush` 等）を主キーとして記述してください。
- **実色カラー見本（プレビュー）の記載義務**:
  - 色を扱うテーブルには、必ず「カラー見本 (Preview)」列を設け、HTMLインラインスタイルによるカラースウォッチを記載してください。
  ```markdown
  | トークン名 | カラー見本 (Preview) | カラーコード | 用途 |
  | :--- | :---: | :--- | :--- |
  | `NeonCyanBrush` | <span style="background-color:#00FFFF; color:#10141B; padding:2px 8px; border-radius:3px; font-weight:bold;">■ #00FFFF</span> | `#00FFFF` | 主要アクション、アクティブ表示 |
  ```
- **タイポグラフィスケールの遵守**:
  - フォントサイズはデザイントークンのスケール（`Display: 24pt`, `Header1: 20pt`, `Header2: 16pt`, `Subheader: 14pt`, `Body: 13pt`, `Caption: 11pt`, `Micro: 9pt`）から選択し、中途半端な独自サイズ（例: 13.5pt, 15ptなど）を新設しないでください。
- **4pxグリッド・スペーシングの遵守**:
  - 余白（Padding, Margin, Gap）は `4pxベースグリッド`（2px, 4px, 8px, 12px, 16px, 24px, 32px）を遵守してください。
- **角丸トークンの遵守**:
  - コントロールには `Radius.Small (4px)`、カード・パネルには `Radius.Medium (8px)`、円形ボタン・バブルには `Radius.Pill (9999px)` を適用してください。

### 3.2 共通コントロールスタイルの適用 (`02_共通コントロールスタイル仕様書.md`)
- コントロールの記述には、共通仕様書で標準化されたバリアント（PrimaryButton, SecondaryButton, SubtleButton, SearchBox, NeonSliderStyle, VirtualizedListBox 等）を明記してください。
- リスト項目には、行選択時の**「左端ネオンシアンアクセント縦バー（幅3px）」**およびホバーハイライト仕様を漏れなく定義してください。

## 4. パフォーマンス最適化方針の遵守

[パフォーマンス最適化詳細設計書](../../設計/詳細設計/パフォーマンス最適化.md) に基づき、以下のルールを仕様書に明記してください：

1. **コレクション表示のUI仮想化必須**:
   - 楽曲一覧、アルバム一覧、プレイリスト項目、再生キューなど、多数のオブジェクトを表示するコントロールには、親 `ScrollViewer` の内包を禁止し、以下のUI仮想化プロパティを必須とします：
     ```xml
     VirtualizingPanel.IsVirtualizing="True"
     VirtualizingPanel.VirtualizationMode="Recycling"
     VirtualizingPanel.ScrollUnit="Pixel"
     ScrollViewer.CanContentScroll="True"
     ```
2. **非表示パネル・ドロワーの完全描画抑止**:
   - 通常時に折りたたまれているパネル（右側スライドパネル、ドロワー、ポップアップ等）は、非表示時に必ず `Visibility="Collapsed"` と連動させる仕様としてください。
3. **高負荷エフェクトの排除**:
   - アニメーションや高頻度更新（スペクトラムバー、シークバー等）を伴う動的要素への `DropShadowEffect` や `BlurEffect` の適用を禁止します。

## 5. マークダウン記述と図表のルール

### 5.1 Mermaid構文の特殊文字クォート規則
Mermaidのパースエラーを防止するため、サブグラフ名やノードラベル内に以下の特殊文字が含まれる場合は、**必ずダブルクォート `["..."]` で保護**してください：
- 丸括弧 `()`、角括弧 `[]`、波括弧 `{}`
- コロン `:`、セミコロン `;`
- シャープ `#`（カラーコード等）
- 改行 `<br/>`
- 算術記号 `+`, `-`, `*`, `/`, `%`
- スラッシュ `/`

```mermaid
%% 良い例 (Good):
flowchart LR
    subgraph Surfaces ["サーフェス層 (Surfaces)"]
        W["WindowBackground<br/>#161920"]:::wBg
    end

%% 悪い例 (Bad - パースエラー):
flowchart LR
    subgraph Surfaces [サーフェス層 (Surfaces)]
        W[WindowBackground<br>#161920]
    end
```

### 5.2 過渡的表現の完全禁止
本プロジェクトの全設計書と同様、UI仕様書内において過渡的表現（「未実装」「現状の」「現状」「今後実装予定」「現行の」など）は**一切使用してはなりません**。
常に**「ToBe（あるべき完成形仕様）」**として客観的・断定的に記述してください。

## 6. UIモックアップ策定方針（ASCIIアートおよびFigma連携）

UI仕様書における画面モックアップは、以下の2段階プロセスに基づき作成・管理します：

1. **ASCIIベースのモックアップ（レイアウト・配置の確定）**:
   - 各仕様書内に、主要オブジェクト仕様（Track, Album, UserPlaylist, PlayQueue, EqualizerPreset, Device等）に基づいた**本来あるべき画面構成（To-Be）**のASCIIアートを記載します。
   - 現在のコードベースの実装状況（仮画面やComing Soon等）に左右されることなく、主要オブジェクト通りの正式なコントロール配置・属性一覧・アクション動線を表現します。
2. **Figmaリンクの設置（グラフィック・スタイルの確定）**:
   - ASCIIベースで部品配置を確定した後、Figmaを用いて詳細なグラフィックデザインを整えます（Figma作成タスクは別タスクとして実施）。
   - UI仕様書には該当Figmaフレームへのリンク（プレースホルダー）を記載します。
3. **XAML画面キャプチャの位置付け（実装比較用）**:
   - tools/MockupRenderer 等によるXAML画面キャプチャは、仕様書本文のモックアップとしては直接配置せず、**Figmaで作成した完成イメージと実際の実装結果との差分比較・検証用**として利用します。
