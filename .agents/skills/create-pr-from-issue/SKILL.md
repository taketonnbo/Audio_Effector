# PR作成スキル (create-pr-from-issue)

このスキルは、ユーザーから「Issueの内容を読み、PRを作成する」という指示を受けた際に使用します。エージェントは以下の手順と規則に従ってタスクを進行してください。

## ワークフロー手順

1. **Issueの把握**:
   - 指定されたIssueの番号またはURLから、要望やバグの内容を正確に読み取ります。
   - 関連するコードベースを調査し、実装計画（Implementation Plan）を策定します。

2. **作業用ブランチの作成**:
   - 指定がなければ、必ず `develop` ブランチから新しい作業用ブランチを作成してください。

3. **実装と確認**:
   - 策定した計画に沿ってコードを修正・追加します。
   - **仕様書の確認と更新**: 実装内容に関連する仕様書（`設計` フォルダ内の `.md` ファイルなど）が存在するか必ず確認し、仕様に変更が生じる場合はあわせて修正対応を行ってください。
   - 完了後、ビルド（`dotnet build`など）を実行してエラーがないことを確認します。

4. **コミット**:
   - 変更をステージング（`git add .`）します。
   - **【重要】コミットルールの順守**: コミットを作成する前に、必ず `rule_docs\git_operation_rules.md` を読み、そこに記載されているコミットルール（プレフィックスの付け方、メッセージのフォーマットなど）を厳格に守ってコミットメッセージを作成してください。
   - `git commit` を実行してコミットを完了します。

5. **PR（Pull Request）の作成**:
   - 作業ブランチをリモートリポジトリにPushします（`git push -u origin <ブランチ名>`）。
   - GitHub CLI (`gh pr create`) などを利用してPRを作成します。
   - **【重要】PRタイトルの命名規則**: 
     - プレフィックスとして `feat:` や `fix:` などの従来のConventional Commitsの英語表記は**使用しないでください**。
     - 代わりに、「[機能追加]」、「[バグ修正]」、「[リファクタ]」などのように、対応の概要を**半角の角括弧 []** で囲ってタイトルの先頭に付与してください。
     - 例: `[機能追加] 基本操作のショートカットキー割り当て (Issue #43)`
   - **PRの説明文 (Body) の記述要件**:
     - 解決するIssue番号（`Resolves #〇〇`）を先頭に記載します。
     - データモデルの変更、ViewModelの拡張、UIコンポーネントの追加など、実装した**具体的な対応内容**をわかりやすく箇条書き等で記載してください。
     - コマンド実行時の文字数制限やエンコーディング問題を回避するため、説明文は一度一時ファイル（例: `pr_desc.md`）に書き出し、`--body-file pr_desc.md` オプションを使用してPRを作成してください（使用後は一時ファイルを削除してください）。

## 注意事項
- PRのターゲット（Base）ブランチは、ユーザーから特別な指示がない限り `develop` となります。デフォルトブランチに作成されてしまった場合は、`gh pr edit <PR番号> --base develop` で修正してください。
