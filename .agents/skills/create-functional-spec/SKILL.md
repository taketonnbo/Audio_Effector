# 機能仕様書作成スキル (create-functional-spec)

このスキルは、ユーザーから「機能仕様書を作成する」よう指示された場合に使用します。エージェントは以下の手順と規則に従って作業を進めてください。

## ワークフロー手順

### 1. ディレクトリとファイルの準備
- プロジェクトルートから `設計/機能仕様/` というディレクトリを使用します（存在しない場合は作成します）。
- そのディレクトリ内に `<機能名>.md` というMarkdownファイルを作成します（ファイル名は必ず日本語にすること）。

### 2. 記述の基本方針（重要）
- **ユーザー目線での記述**: ソースコードベースや内部実装のロジック（クラス名や変数名、DB構造など）を説明するのではなく、**ユーザー視点でどのような機能が提供されるか**を中心に記述してください。
- ユーザーがどのような目的で、どのように操作し、どのような結果が得られるか（メリット）に焦点を当てます。

### 3. 仕様書のフォーマット
作成するMarkdownファイルには、以下のセクションを含めて構成してください。

- `## 1. 機能概要`: この機能が何をするためのものか、その目的と全体像。
- `## 2. ユーザー向け提供機能`:
  - サブセクション (`### 2.1`, `### 2.2`...) を用い、各要素や画面の具体的な機能を詳細に説明します。
  - ユーザーに提供される価値や振る舞いを箇条書きなどを活用して分かりやすく記載します。
- `## 3. 利用手順（想定ワークフロー）`:
  - ユーザーが実際にこの機能を利用する際の一連の操作ステップを番号付きリスト（1. 2. 3...）で記述します。

### 4. Git操作 (任意)
- ユーザーから「対応を進めて」「PRを作成して」などの指示がある場合は、`rule_docs/git_operation_rules.md` のコミットルールに従い、コミットとPR作成を行ってください。
