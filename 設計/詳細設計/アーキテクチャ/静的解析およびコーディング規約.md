# 静的解析およびコーディング規約 仕様書

## 1. 概要

### 1.1 目的
本ドキュメントは、AudioEffector におけるコード品質の統一、保守性の向上、およびドキュメント（DocFX）の正確性を担保するための **静的解析ルール（Roslyn Analyzers / .editorconfig）** および **XMLドキュメントコメント制約** を定義する仕様書です。
開発者が実装を行う際、ビルド時およびエディタ上でリアルタイムに制約が適用され、統一された美しいコードベースを維持することを目的とします。

### 1.2 適用範囲
- **`AudioEffector` プロジェクト**: 本規約およびXMLドキュメント制約を完全適用します。
- **`AudioEffector.Tests` プロジェクト**: コード品質・命名規則は適用しますが、XMLドキュメントコメント制約は除外します（テストコードの可読性・記述性を優先するため）。

---

## 2. XMLドキュメントコメント制約

すべての `public`（公開）な型およびメンバーに対して、XMLドキュメントコメントの記述を義務付けます。

### 2.1 必須記載要件一覧

| 対象 | 必須タグ | 任意・不要なタグ | 備考 |
| :--- | :--- | :--- | :--- |
| **公開クラス・インターフェース・構造体・レコード・Enum** | `<summary>` | `<remarks>`, `<example>` | その型が何を表し、どんな責務を持つかを1〜2行で簡潔に記述。 |
| **公開メソッド (public method)** | ・`<summary>`<br>・`<param name="...">`<br>・`<returns>` (void以外) | **`<exception>` (不要)** | ・すべての引数に対して `<param>` を記述。<br>・戻り値が存在する場合は `<returns>` を記述。<br>・**例外（`<exception>`）の記述は不要・任意** とします。 |
| **公開プロパティ (public property)** | `<summary>` | `<value>` (不要) | プロパティが保持する値・状態の意味を記述。 |
| **公開イベント (public event)** | `<summary>` | なし | イベントがいつ発行されるかの条件を記述。 |

---

### 2.2 メソッドの記述例

#### 良い例 ✅ (Good)
```csharp
/// <summary>
/// 指定されたトラックの再生を開始します。
/// </summary>
/// <param name="trackId">再生対象のトラックID。</param>
/// <param name="cancellationToken">キャンセレーショントークン。</param>
/// <returns>非同期タスク。</returns>
public async Task PlayTrackAsync(TrackId trackId, CancellationToken cancellationToken = default)
{
    // ...
}

/// <summary>
/// 2つのゲイン値を加算し、許容範囲内にクランプした結果を返します。
/// </summary>
/// <param name="left">加算元のゲイン。</param>
/// <param name="right">加算するゲイン。</param>
/// <returns>加算後のゲイン値。</returns>
public static Gain Add(Gain left, Gain right)
{
    // ...
}
```

#### 悪い例 ❌ (Bad)
```csharp
// ❌ XMLコメント自体がない
public async Task PlayTrackAsync(TrackId trackId) { ... }

// ❌ <param> や <returns> が抜けている
/// <summary>
/// トラックを再生します。
/// </summary>
public async Task<bool> PlayTrackAsync(TrackId trackId) { ... }
```

## 3. 静的解析（Static Analysis）ルール設計

### 3.1 導入するアナライザパッケージ
プロジェクトには以下の公式・標準Roslynアナライザを導入します。

1. **`Microsoft.CodeAnalysis.NetAnalyzers`**: .NET公式の品質・パフォーマンス・セキュリティ解析
2. **`StyleCop.Analyzers`**: コードスタイル・レイアウト・XMLドキュメントコメント解析

---

### 3.2 ルール適用方針（有効化 vs 無効化・緩和）

開発効率を損なう過度なルールや英語定型文の強制は無効化（None）し、本質的な品質・XMLコメント制約のみを警告（Warning）またはエラー（Error）として有効化します。

#### ① 有効化・強制する主なルール (Warning / Error)

| ルールID | 種別 | 説明 |
| :--- | :--- | :--- |
| **`CS1591`** | Compiler | 公開されている型またはメンバーの XML コメントの欠落検知 |
| **`SA1600`** | StyleCop | public 要素に対する XML ドキュメントコメントの必須化 |
| **`SA1611`** | StyleCop | メソッドのすべての引数に対する `<param>` タグ記述の必須化 |
| **`SA1615`** | StyleCop | 戻り値を持つメソッドに対する `<returns>` タグ記述の必須化 |
| **`SA1618`** | StyleCop | ジェネリック要素に対する `<typeparam>` タグ記述の必須化 |
| **`CA1822`** | NetAnalyzer | 状態にアクセスしないメンバーの static 化推奨 |
| **`CA1806`** | NetAnalyzer | メソッドの戻り値が意図せず無視されている場合の警告 |
| **`CA2000`** | NetAnalyzer | IDisposable オブジェクトの破棄漏れ検知 |

#### ② 意図的に無効化・緩和するルール (None)

| ルールID | 無効化する理由 |
| :--- | :--- |
| **`SA1633`** (File Header) | ファイル先頭への著作権ヘッダー記述の強制。個人開発およびGit履歴管理があるため不要。 |
| **`SA1623`** (Property Summary Prefix) | 「Gets or sets a value indicating whether...」などの英語定型文の強制。日本語での自由なドキュメント記述を阻害するため無効化。 |
| **`SA1629`** (Documentation Text Ending) | コメント末尾のピリオド（句点）強制。日本語コメントで不自然になるため無効化。 |
| **`SA1642` / `SA1643`** (Constructor Summary) | コンストラクタやファイナライザに対する定型コメント強制の無効化。 |
| **`SA1101`** (Prefix this.) | `this.` プレフィックスの強制を無効化（privateフィールドは `_` プレフィックスを使用）。 |
| **`SA1200`** (Using Outside Namespace) | `using` ディレクティブの配置位置（ファイル先頭 vs namespace内）の強制を無効化。 |
| **`SA1652`** (Enable XML Documentation) | プロジェクトファイル設定時の重複警告を抑制。 |

## 4. 命名規則およびコーディング規約

### 4.1 識別子の命名規則

| 対象 | 規則 | 例 |
| :--- | :--- | :--- |
| **クラス・構造体・レコード** | `PascalCase` | `Track`, `EqualizerPreset`, `Gain` |
| **インターフェース** | `IPascalCase` (`I`プレフィックス) | `ITrackRepository`, `IAudioEngine`, `IEventBus` |
| **メソッド** | `PascalCase` | `PlayTrackAsync`, `CalculateSpectrum` |
| **非同期メソッド** | **`PascalCaseAsync` (末尾 `Async` 必須)** | `GetByIdAsync`, `SaveAsync`, `TransferFileAsync` |
| **プロパティ・イベント** | `PascalCase` | `Title`, `Duration`, `TrackChanged` |
| **引数・ローカル変数** | `camelCase` | `trackId`, `cancellationToken`, `sampleRate` |
| **private フィールド** | `_camelCase` (`_`プレフィックス) | `_audioEngine`, `_trackRepository` |
| **定数 (const / static readonly)** | `PascalCase` | `SpectrumBassScale`, `DefaultSampleRate` |
| **Enum型およびメンバー** | `PascalCase` | `PlaybackState.Playing`, `ViewType.Albums` |

---

### 4.2 コードスタイル基準
1. **Null許容参照型の厳格利用 (`<Nullable>enable</Nullable>`)**:
   - `null` を許容する場合は明示的に `string?` や `Track?` と記述し、NullReferenceException を根絶します。
2. **イミュータビリティ（不変性）の優先**:
   - 値オブジェクトやドメインイベントには `readonly record struct` または `record` を使用します。
   - コレクションを外部に公開する場合は、`IReadOnlyList<T>` や `IReadOnlyCollection<T>` を使用します。
3. **インデントと改行**:
   - インデント: 半角スペース 4 文字（タブ文字は使用しない）。
   - 改行コード: `CRLF`（Windows環境標準）。
   - 文字コード: `UTF-8` (BOM付きまたはBOMなし)。
