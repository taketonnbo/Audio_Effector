# ドメイン層 詳細設計書

## 1. 概要

### 1.1 目的
本ドキュメントは、AudioEffector における **ドメイン層（Domain Layer）** の設計仕様書です。
ドメイン層はアプリケーションの最も中核となる業務概念・データ構造・計算ルールを表現し、UIフレームワーク（WPF）や外部ライブラリ（NAudio, TagLib, MediaDevices等）に一切依存しない純粋なC#で構成されます。

### 1.2 設計原則
1. **完全な純粋性**: `System.*` などのC#標準ライブラリのみに依存し、サードパーティライブラリやUI名前空間（`System.Windows.*` 等）を参照してはならない。
2. **自己カプセル化と不変条件の保護**: エンティティや値オブジェクトは不正な状態（例: 負の音量、範囲外の周波数など）にならないよう自身のルールで検証する。
3. **外部通知・I/Oの非保持**: ドメイン層自身はEventBusや外部通信を行わない（イベント発行は上位のApplication層が担当する）。

---

## 2. 名前空間とディレクトリ構造

ドメイン層は `AudioEffector.Domain` をルート名前空間とし、以下のサブ名前空間に分類して管理します。

```
AudioEffector/
└── Domain/                                      # [名前空間: AudioEffector.Domain]
    ├── Entities/                                # エンティティ (IDを持ちライフサイクルがあるモデル)
    │   └── DataTransfer/                        # ポータブルデバイス・転送用モデル
    ├── ValueObjects/                            # 値オブジェクト (不変な値の表現)
    ├── Events/                                  # ドメインイベント (発生した出来事を表すレコード型)
    ├── Services/                                # ドメインサービス (純粋な計算・アルゴリズム)
    └── Repositories/                            # リポジトリおよび外部アクセスのインターフェース (I/F)
```

---

## 3. 各コンポーネントの配置基準と実装ルール

### 3.1 Entities (`AudioEffector.Domain.Entities`)
- **配置基準**: 一意の識別子（ID）を持ち、属性が変化しても同一性が保たれるオブジェクト（楽曲、アルバム、プレイリスト、EQプリセット、データ転送モデル等）。
- **実装ルール**:
  - クラスとして定義し、ビジネスルールおよびデータ整合性をカプセル化する。
  - 旧アーキテクチャの `AudioEffector/Models/` は完全に撤廃され、本ドメインエンティティ群へ完全統合済み。
  - UIバインディングとの高い互換性・即応性を維持するため、変更通知（`INotifyPropertyChanged`）やUI用プロパティをサポートする。

#### 主要エンティティ一覧
| エンティティ名 | 名前空間 | 役割・説明 |
| :--- | :--- | :--- |
| `Track` | `AudioEffector.Domain.Entities` | 楽曲ファイル情報、音質ラベル、再生状態、お気に入り状態等をカプセル化 |
| `Album` | `AudioEffector.Domain.Entities` | アルバム情報、所属トラック一覧、ハイレゾ/ロスレス含有判定、UI選択伝播 |
| `UserPlaylist` | `AudioEffector.Domain.Entities` | ユーザー作成プレイリスト、トラックパス一覧、サムネイル表示コレクション |
| `EqualizerPreset` | `AudioEffector.Domain.Entities` | 10バンドEQプリセット名・各バンドゲイン値（presets.jsonと完全互換） |
| `DeviceAlbum` | `AudioEffector.Domain.Entities.DataTransfer` | MTPデバイス上のアルバムフォルダ情報、トラック一覧、カバー画像 |
| `DeviceTrack` | `AudioEffector.Domain.Entities.DataTransfer` | MTPデバイス上の楽曲ファイル情報、パス、ファイルサイズ |

### 3.2 Value Objects (`AudioEffector.Domain.ValueObjects`)
- **配置基準**: 識別子を持たず、属性の値そのものによって識別されるイミュータブル（不変）なオブジェクト（音量、周波数帯域、ゲイン値、再生時間位置、ファイルパス等）。
- **実装ルール**:
  - C# の `readonly record struct` または `record` として定義する。
  - コンストラクタやファクトリメソッドでバリデーション（値の範囲チェック等）を行い、常に有効な値のみを保持する。

### 3.3 Domain Events (`AudioEffector.Domain.Events`)
- **配置基準**: ドメイン内で発生した重要かつ過去の出来事（曲の変更、再生状態の変更、音量の変更、プレイリストの更新等）。
- **実装ルール**:
  - `IDomainEvent`（`OccurredOn` を持つ共通I/F）を実装する `record` 型として定義する。
  - イベントデータは不変（イミュータブル）とし、発生時点の確定情報を保持する。

### 3.4 Domain Services (`AudioEffector.Domain.Services`)
- **配置基準**: 単一のエンティティや値オブジェクトの責務に収まらない、純粋な業務計算やアルゴリズム（スペクトラムアナライザの周波数別振幅・チルト補正計算、シャッフル/リピートの再生順序決定アルゴリズム等）。
- **実装ルール**:
  - 状態を持たない（ステートレスな）クラスとして実装する。
  - 外部I/O（ファイル読み書きやAPI通信）を一切行わず、引数として受け取ったデータから計算結果を返す。

### 3.5 Repository Interfaces (`AudioEffector.Domain.Repositories`)
- **配置基準**: ドメインモデルを永続化（保存・取得・検索・削除）するための抽象インターフェース。
- **実装ルール**:
  - `IxxxRepository` という命名規則でインターフェースのみを定義する（実装クラスはInfrastructure/Repository層に配置する）。
  - 非同期メソッドは末尾に `Async` を付与し（例: `GetByIdAsync`, `SaveAsync`）、ドメインエンティティの入出力を基本とする。

## 4. 新規コード追加時のチェックリスト

ドメイン層に新しいコードを追加する際は、以下を満たしているか確認してください。

- [ ] 外部I/O（ファイルアクセス、ネットワーク、EventBus発行）を直接呼んでいないか？
- [ ] 値オブジェクトは `record` 等で不変に保たれているか？
- [ ] 不正な値の生成を防ぐバリデーションが実装されているか？
