# ドメイン層 詳細設計書

## 1. 概要

### 1.1 目的
本ドキュメントは、AudioEffector における **ドメイン層（Domain Layer）** の設計仕様書です。
ドメイン層はアプリケーションの最も中核となる業務概念・データ構造・計算ルールを表現します。

### 1.2 設計原則
1. **ドメインの独立性とWPF非依存方針**:
   - ドメイン層（`AudioEffector.Domain`）は `net8.0` の純粋な C# クラスライブラリとして構成し、外部 I/O ライブラリ（TagLibSharp 等）および UI フレームワーク（WPF: `System.Windows.*`）へ一切依存しないものとします。
   - 現行単一プロジェクトで一時的に残存していた `Track` / `Album` / `DeviceAlbum` の `BitmapImage`・遅延タグ読込（`TagLib` / `Dispatcher`）および `AppSettings` の `System.Windows.Input.Key` / `ModifierKeys` は、Issue #298 の分離設計に基づき Issue #303 にて完全撤去・WPF 非依存型へ置換済みです（詳細は「4. WPF直接依存の分離設計（#298 / #303 完了）」を参照）。
2. **自己カプセル化と不変条件の保護**: エンティティや値オブジェクトは不正な状態（例: 負の音量、範囲外の周波数・ゲインなど）にならないよう自身のルールで検証します。
3. **外部通知・永続化I/Oの非保持**: ドメイン層自身はEventBus発行やファイル永続化I/Oを直接行いません（イベント発行はApplication層、永続化実装はInfrastructure層が担当します）。

## 2. 名前空間とディレクトリ構造

ドメイン層は `AudioEffector.Domain` をルート名前空間とし、以下のサブ名前空間に分類して管理します。

```
AudioEffector.Domain/                            # [Class Library / net8.0] [名前空間: AudioEffector.Domain]
├── Entities/                                    # エンティティ (ライフサイクルを持つ中核モデル)
│   └── DataTransfer/                            # ポータブルデバイス・転送用モデル
├── ValueObjects/                                # 値オブジェクト (不変な値の表現)
├── Events/                                      # ドメインイベント (発生した出来事を表すレコード型)
├── Services/                                    # ドメインサービス (純粋な計算・照合アルゴリズム)
└── Repositories/                                # リポジトリおよび外部アクセスのインターフェース (I/F)
```

## 3. 各コンポーネントの配置基準と実装ルール

### 3.1 Entities (`AudioEffector.Domain.Entities`)
- **配置基準**: 属性が変化しても同一性が保たれる中核オブジェクト（楽曲、アルバム、プレイリスト、お気に入り・再生履歴エントリ、EQプリセット、アプリ設定、データ転送モデル）。
- **実装ルール**:
  - ビジネスルールおよびデータ整合性をカプセル化する。
  - UIバインディングで直接参照されるエンティティは `INotifyPropertyChanged` による変更通知をサポートする。

#### 主要エンティティ一覧
| エンティティ名 | 名前空間 | 役割・説明 |
| :--- | :--- | :--- |
| `Track` | `AudioEffector.Domain.Entities` | 楽曲ファイル情報、所属アルバムID（`AlbumId`）、音質ラベル（`QualityInfo` / `QualityLabel`）、再生状態、お気に入り状態、選択状態等を保持 |
| `Album` | `AudioEffector.Domain.Entities` | アルバムID（`Id`）、アルバム情報、所属トラック一覧、代表トラックパス（`RepresentativeTrackFilePath`）、ハイレゾ/ロスレス含有判定、UI選択伝播 |
| `FavoriteTrackEntry` | `AudioEffector.Domain.Entities` | お気に入り楽曲のメタデータ識別情報（`Title`, `Artist`, `Album`, `TrackNumber`, `DurationSeconds`, `LastKnownFilePath`, `AddedAt`）を保持 |
| `RecentTrackEntry` | `AudioEffector.Domain.Entities` | 最近再生した曲の履歴エントリ（`Track`, `PlayedAt`, `PlayedAtDisplay`）およびライブラリ実体差し替え（`WithTrack`）を提供 |
| `UserPlaylist` | `AudioEffector.Domain.Entities` | ユーザー作成プレイリスト（`Id`, `Name`, `TrackIds`, `TrackPaths`, `CreatedAt`, `UpdatedAt`, 2×2サムネイル `Thumbnail1`〜`4`） |
| `EqualizerPreset` | `AudioEffector.Domain.Entities` | 10バンドEQプリセット名・バンド構成（`Bands` / `Gains`）・カスタム判定（`IsCustom`） |
| `AppSettings` | `AudioEffector.Domain.Entities` | テーマ、音量、サンプルレート、バッファサイズ、イコライザー設定、WPF非依存のショートカットキー割当て（`ShortcutKeyConfig` / `ShortcutModifiers`）、ミニプレイヤー座標・最前面挙動等の設定モデル |
| `DeviceAlbum` | `AudioEffector.Domain.Entities.DataTransfer` | 外部デバイス上のアルバムフォルダ情報、トラック一覧（※カバーアート描画はPresentation層へ分離） |
| `DeviceTrack` | `AudioEffector.Domain.Entities.DataTransfer` | 外部デバイス上の楽曲ファイル情報、パス、ファイルサイズ |
| `LyricsDocument` | `AudioEffector.Domain.Entities` | 楽曲に対応する不変歌詞データ全体（`Lines`, `IsSynced`, `Title`, `Artist`, `Album`, `Author`, `Offset`, `SourceType`, `SourcePath`）。`[offset:]` 補正（0 秒未満クランプ）を考慮した O(log N) 二分探索による現在行特定（`FindActiveLineIndex` / `FindActiveLineRange`）およびシーク位置計算（`GetEffectiveTimestamp` / `GetSeekPosition`）を提供 |

### 3.2 Value Objects (`AudioEffector.Domain.ValueObjects`)
- **配置基準**: 識別子を持たず、属性の値そのものによって識別される不変オブジェクト（`AlbumId`, `AudioPath`, `FrequencyBand`, `Gain`, `LyricLine`, `LyricsSourceType`, `PlaybackState`, `PlaylistId`, `TimePosition`, `TrackId`, `Volume`）。
- **実装ルール**:
  - `readonly record struct` または `record` として定義し、コンストラクタやファクトリメソッドで値の範囲検証・クランプを行う。
  - `AlbumId` は `TrackId` / `PlaylistId` と同一の `readonly record struct` 規約（`Guid.Empty` 拒否、`New()` / `From(Guid)` / `From(string)`）に準拠し、純粋な一意識別子として定義する。
  - `LyricLine` は歌詞 1 行（0 始まり `Index`, `TimeSpan? Timestamp`, `string Text`, `IsInstrumental`, `IsSeekable`）を不変 `record` として表現し、`LyricsSourceType` は取得元種別（`None` / `LrcFile` / `EmbeddedTag`）を列挙体で定義する。

### 3.3 Domain Events (`AudioEffector.Domain.Events`)
- **配置基準**: ドメイン内で発生した出来事（`TrackChangedEvent`, `PlaybackStateChangedEvent`, `VolumeChangedEvent`, `PlaylistUpdatedEvent`, `EqualizerPresetChangedEvent`, `LyricsUpdatedEvent`）。
- **実装ルール**:
  - `IDomainEvent`（`OccurredOn` を持つ共通I/F）を実装する不変の `record` 型として定義する。

### 3.4 Domain Services (`AudioEffector.Domain.Services`)
- **配置基準**: 単一のエンティティや値オブジェクトの責務に収まらない純粋な計算・照合アルゴリズムおよびドメインポート契約。
  - `ISpectrumCalculator` / `SpectrumCalculator`: FFT複素数結果から対数周波数スケール（20Hz〜20kHz）に基づくバンド別振幅・チルト補正を計算。
  - `FavoriteTrackMatcher`: お気に入りエントリとライブラリの楽曲を3段階（①未タグ/旧形式のパス優先照合 → ②曲名・アーティスト・アルバム・トラック番号・再生時間±5秒許容のメタデータ照合 → ③パスフォールバック）で照合し、ファイル移動やフォーマット差し替えに追従。
  - `AlbumGroupingResolver`: 楽曲群を作品単位のグループ（共通 `Track.AlbumArtist` 優先、未設定コンピレーションは同一ディレクトリ・連番トラック番号・フォルダ名に基づく `"Various Artists"` フォールバック）へ集約し、既存の `AlbumId` を引き継ぎつつ未採番グループへ `AlbumId.New()` を割り当てる。
  - `IPlaybackOrderStrategy`（`SequentialPlaybackStrategy`, `RepeatPlaybackStrategy`, `ShufflePlaybackStrategy`）: 再生順序決定戦略。
  - `ILrcParser`: LRC 形式テキストの解析（`Parse`）および LRC 形式へのシリアライズ（`Format`）を定義するポート契約（LRC 自動生成 #101 とも共有）。
  - `ILyricsProvider`: 指定 `Track` から歌詞データ（`LyricsDocument?`）を非同期取得するポート契約。
- **実装ルール**:
  - 外部I/Oを一切行わず、引数として受け取ったデータから決定論的または純粋な計算結果を返す。

### 3.5 Repository Interfaces (`AudioEffector.Domain.Repositories`)
- **配置基準**: ドメインモデルを永続化・取得するための抽象インターフェース（`ITrackRepository`, `IPlaylistRepository`, `IFavoriteRepository`, `IRecentTrackRepository`, `ISettingsRepository`, `IDataTransferRepository`）。
- **実装ルール**:
  - `IxxxRepository` という命名規則でインターフェースのみを定義する（具象クラスは `Infrastructure/Repository` または `Infrastructure/DataTransfer` に配置）。
  - 非同期I/Oを伴うメソッドには末尾に `Async` を付与する（例: `IFavoriteRepository.GetAllEntriesAsync`, `SaveAllAsync`）。なお、UIスレッドや起動時に即時同期アクセスを行う軽量リポジトリ（`IRecentTrackRepository.Load()` / `Save()` 等）は同期契約として定義する。

## 4. WPF直接依存の分離設計（#298 / #303 完了）

`AudioEffector.Domain` を `net8.0`・外部依存ゼロのライブラリとして独立させるため、ドメインエンティティに残存していた WPF 直接依存（計 4 ファイル）は以下の設計に従い Issue #303 にてすべて分離済みです。

### 4.1 `Track` / `Album` / `DeviceAlbum` の画像・Dispatcher 依存分離

#### 現状の依存箇所と参照元棚卸し
| エンティティ | 削除対象メンバー | 現状の参照元（Presentation / Tests） |
| :--- | :--- | :--- |
| `Track` | `BitmapImage? AlbumArt`（静的 `_artCache`、`TagLib.File.Create`、`Dispatcher.Invoke` 含む） | **参照ゼロ（死蔵コード）**。一覧系 XAML はすべて `Presentation.AttachedProperties.AlbumArtLoader.SourcePath` を使用。 |
| `Track` | `BitmapImage? CoverImage` | ・`MainViewModel.cs`（`LoadTrack` 内のキャッシュ設定と未使用化する `_albumArtCache`）<br>・`PlayerControlViewModel.cs`（`UpdateTrackDisplays` 内の `track.CoverImage != null` 分岐）<br>・`PlayerControlViewModelTests.cs`（初期化子 `CoverImage = null`） |
| `Album` | `BitmapImage? CoverImage` | ・`LibraryViewModel.cs`（生成時の `CoverImage = null` 代入 1 箇所のみ）<br>・XAML 参照ゼロ（`AlbumDetailView.xaml` の `CoverImage` は `AlbumDetailViewModel.CoverImage` をバインド） |
| `DeviceAlbum` | `BitmapImage? CoverImage` | **参照ゼロ**（`DeviceSyncView.xaml` は `AlbumArtLoader.SourcePath="{Binding Tracks[0].FilePath}"` を使用）。 |

#### 分離方式の比較と選定
| 方式 | 概要 | 判定・理由 |
| :--- | :--- | :--- |
| **案A（採用）: エンティティから画像プロパティを撤去し Presentation 層へ統一** | `CoverImage` / `AlbumArt` をドメインエンティティから削除し、一覧表示は既存 `AlbumArtLoader.SourcePath`、詳細・再生中表示は各 ViewModel での `FilePath` 起点非同期デコードへ統一する。 | **採用**。XAML 変更ゼロで既存の一覧仮想化パフォーマンスと高解像度表示を維持でき、ドメイン層のメモリ負荷も最小化できる。 |
| 案B（不採用）: エンティティに `byte[]?` を保持 | 画像バイト列をドメインモデルに保持し、Converter 等で `BitmapImage` 化する。 | 不採用。数千〜数万曲のスキャン時に全エンティティが画像バイナリを保持しメモリ使用量が激増する。 |
| 案C（不採用）: UI ラッパー ViewModel を全エンティティへ新設 | `TrackViewModel` / `AlbumViewModel` を新設して画像を保持する。 | 不採用。既存一覧 XAML は既に `AlbumArtLoader.SourcePath` へ移行済みであり、全面改修のコストに見合う利点がない。 |

### 4.2 `AppSettings` / `ShortcutKeyConfig` のショートカットキー型分離

#### 既存 `settings.json` のシリアライズ形式と後方互換要件
- `SettingsApplicationService` は `System.Text.Json.JsonSerializer` の既定設定（`JsonStringEnumConverter` なし、`WriteIndented = true` のみ）で `AppSettings` を `%APPDATA%\AudioEffector\settings.json` へ保存・復元しています。
- そのため、既存ユーザーの `settings.json` には `Key` および `Modifiers` が **WPF 列挙体の基底整数値（`int`）** として保存されています（例: `{"Key": 18, "Modifiers": 2}` = `Ctrl + Space`、`None = 0`）。

#### WPF 非依存モデル設計
既存 `settings.json` との **100% 双方向互換（デシリアライズ／再シリアライズとも同一 JSON 表現）** を保証するため、JSON プロパティ名（`Key`, `Modifiers`）と整数値表現を維持したまま、ドメイン層に以下の WPF 非依存型を定義します。

```csharp
/// <summary>
/// ショートカットキーの修飾キーフラグ（WPF ModifierKeys とビット値互換）
/// </summary>
[Flags]
public enum ShortcutModifiers
{
    None = 0,
    Alt = 1,
    Control = 2,
    Shift = 4,
    Windows = 8
}

/// <summary>
/// キーボードショートカットの設定を保持するモデル（WPF非依存）
/// </summary>
public class ShortcutKeyConfig
{
    /// <summary>未割り当てを表すキーコード定数</summary>
    public const int NoneKey = 0;

    /// <summary>対象キーコード（WPF System.Windows.Input.Key の整数値と 1:1 互換、0 は未割り当て）</summary>
    public int Key { get; set; } = NoneKey;

    /// <summary>修飾キーフラグ</summary>
    public ShortcutModifiers Modifiers { get; set; } = ShortcutModifiers.None;
}
```

- **後方互換性の保証**:
  - `Key` を `int`（既定値 `0`）、`Modifiers` をビット値一致の `[Flags] enum ShortcutModifiers`（`None=0, Alt=1, Control=2, Shift=4, Windows=8`）とすることで、カスタム `JsonConverter` を追加せずとも既存の `settings.json` をそのまま読み書きでき、旧バージョンとの互換性も維持されます。
  - 主キー（170 種以上の WPF `Key` 値）の変換・妥当性検証（未定義整数値の `Key.None` フォールバック）および `ModifierKeys` との相互変換は、Presentation 層の `ShortcutKeyHelper` に集約します（詳細は [プレゼンテーション層詳細設計書](プレゼンテーション層詳細設計書.md) を参照）。

## 5. 新規コード追加時のチェックリスト

- [ ] ドメイン層から WPF（`System.Windows.*`）や外部I/Oライブラリ（TagLibSharp, NAudio等）を参照していないか？
- [ ] ドメインサービスや値オブジェクトから外部I/O（ファイルアクセス、ネットワーク、EventBus発行）を直接呼んでいないか？
- [ ] 値オブジェクトやドメインイベントは不変（イミュータブル）に保たれているか？
- [ ] 不正な値の生成を防ぐバリデーションが実装されているか？
