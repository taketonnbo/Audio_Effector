# アプリケーション層 詳細設計書

## 1. 概要

### 1.1 目的
本ドキュメントは、AudioEffector における **アプリケーション層（Application Layer / ApplicationServices）** の設計仕様書です。
アプリケーション層はプレゼンテーション層（ViewModel）からの操作要求を受け付け、ドメインモデル・リポジトリ・外部エンジンを連携させて一連の業務処理を実行・調整する役割を担当します。

### 1.2 設計原則
1. **UIフレームワーク非依存**: WPF特有のコントロールやUIスレッド（`Dispatcher`）に直接依存せず、純粋なC#ロジックとして完結させる。
2. **直感的な業務メソッドの提供**: 関連する業務操作ごとにまとまった分かりやすいメソッド名（`PlayTrackAsync`, `PauseAsync`, `SeekAsync`, `SetVolumeAsync`, `ScanFolderAsync` 等）を公開し、処理成否は必要に応じて `Result` / `Result<T>` で返却する。
3. **イベント発行の単一責任**: 処理が正常に完了した後の「ドメインイベントの発行（`IEventBus.PublishAsync`）」はアプリケーション層（`ApplicationService`）が一括して担当する。

## 2. 名前空間とディレクトリ構造

アプリケーション層は `AudioEffector.Application` をルート名前空間とし、以下の構成で管理します。

```
AudioEffector.Application/                       # [Class Library / net8.0] [名前空間: AudioEffector.Application]
├── DependencyInjection.cs                       # AddApplicationServices() DI登録拡張
├── Common/                                      # 共通基盤 (EventBus, 共通インターフェース, 結果型)
│   ├── IEventBus.cs                             # イベント発行・購読インターフェース
│   ├── InMemoryEventBus.cs                      # インメモリイベントバス具象実装
│   ├── IHandle.cs                               # イベントハンドラーインターフェース
│   ├── IAudioEngine.cs                          # 音声再生エンジンの抽象I/F
│   ├── IMetadataExtractor.cs                    # メタデータ・カバーアート抽出の抽象I/F
│   ├── IUiDispatcher.cs                         # UIスレッドディスパッチの抽象I/F
│   ├── ImmediateUiDispatcher.cs                 # ヘッドレス/MCP/テスト向けの既定ディスパッチャー
│   ├── IDataDirectoryProvider.cs                # 永続化データディレクトリ解決の抽象I/F
│   ├── DataDirectoryProvider.cs                 # 永続化データディレクトリ解決の標準実装
│   ├── IJsonFileLockHelper.cs                   # プロセス間ファイルロック・原子的書込・鮮度監視の抽象I/F
│   ├── FileMetadataSnapshot.cs                  # ファイル存在・更新日時・サイズの不変スナップショット
│   ├── FileLockTimeoutException.cs              # ファイルロック取得タイムアウト専用例外
│   ├── LogDescriptionAttribute.cs               # ログ出力用説明属性
│   ├── FftComplex.cs                            # FFT複素数結果の軽量値型構造体（外部DSP非依存）
│   ├── FftEventArgs.cs                          # FFT計算結果通知イベント引数
│   ├── LrcTransferOptions.cs                    # 機器転送時の種別別 .lrc 同梱オプション
│   ├── CompanionLrcResolver.cs                  # 音声ファイル同階層 .lrc の安全読み込み・種別判定ヘルパー
│   └── Result.cs                                # 処理成否・エラー返却用型 (Result / Result<T>)
└── ApplicationServices/                         # アプリケーションサービス群
    ├── AudioApplicationService.cs               # 音声再生・一時停止・停止・シーク・音量制御
    ├── IAudioService.cs                         # オーディオ再生・キュー・EQ統括サービスインターフェース
    ├── LibraryApplicationService.cs             # フォルダスキャン・検索・ソート・お気に入りメタデータ照合と整合
    ├── PlaylistApplicationService.cs            # プレイリスト作成・削除・楽曲追加・除外・並び替え
    ├── EqualizerApplicationService.cs           # EQプリセット管理（presets.json永続化）・バンドゲイン調整
    ├── DataTransferApplicationService.cs        # 外部デバイス検出・楽曲転送・削除
    ├── SettingsApplicationService.cs            # アプリケーション設定のロード・セーブ
    ├── ISettingsService.cs                      # 設定サービスインターフェース
    ├── LyricsApplicationService.cs              # 楽曲歌詞の非同期読み込み・LRUキャッシュ・キャッシュ無効化と更新通知
    └── LrcGenerationApplicationService.cs       # LRC自動生成（文字コード検査・テキスト生成・音声直接文字起こし・モデル管理・保存後即時反映連携）
```

## 3. 各コンポーネントの責務と契約

### 3.1 ApplicationServices (`AudioEffector.Application.ApplicationServices`)
機能カテゴリごとに業務シナリオを進行するオーケストレーターです（実コードの正本は [`AudioEffector.Application/ApplicationServices/`](../../../AudioEffector.Application/ApplicationServices) 配下を参照）。

| サービスクラス / I/F | 主な責務と契約 |
| :--- | :--- |
| `AudioApplicationService` | `IAudioEngine`・`ITrackRepository`・`IEventBus` を連携し、トラック再生（`PlayTrackAsync(TrackId)` → `Task<Result>`）、一時停止（`PauseAsync`）、再開（`ResumeAsync`）、停止（`StopAsync`）、シーク（`SeekAsync(TimePosition)`）、音量変更（`SetVolumeAsync(Volume)`）を実行して対応するドメインイベントを発行する |
| `IAudioService` | NAudio再生パイプライン、予約キュー（`UserQueue`）・アルバムキュー（`AlbumQueue`）、シャッフル・リピート、10バンドEQ、FFT計算通知、および再生終了検知（`TrackPlaybackEnded`）を統括するコアサービス契約 |
| `LibraryApplicationService` | `IMetadataExtractor` を介した指定フォルダからの音声ファイルスキャン、検索・ソート、および `IFavoriteRepository` と `FavoriteTrackMatcher` を用いたお気に入り状態の照合・マイグレーション・自動パス修復（`FavoriteReconciliationResult`）を担う |
| `PlaylistApplicationService` | `IPlaylistRepository` と連携し、プレイリストの作成・リネーム・削除・トラック追加/除外・順序変更（`ReorderTrackAsync`）および `PlaylistUpdatedEvent` の発行を担う |
| `EqualizerApplicationService` | 組み込みプリセットおよびカスタムプリセット（設定リポジトリで名前単位に排他更新）、各周波数バンドのゲイン変更、設定連携を担う |
| `DataTransferApplicationService` | `IDataTransferRepository`・`IAudioTranscodeService`・`ISettingsService`・`ILrcParser` を連携し、接続デバイスのトラック/アルバム一覧取得、形式変換を伴う楽曲転送、設定に基づく種別別 `.lrc` 補助ファイルの同梱転送（`TransferCompanionFileAsync`、例外時はログのみ記録し音声転送を継続）、およびデバイス上トラックの削除を担う |
| `SettingsApplicationService` (`ISettingsService`) | DI 注入された `ISettingsRepository`・`IDataDirectoryProvider`・`IJsonFileLockHelper` を介して `AppSettings`（`settings.json`）およびキー設定のプロセス間安全な読み込み・保存を担う。個々の設定変更は `UpdateSettings` / `UpdateSettingsAsync` に渡し、同じロック内で最新の設定を読み込み、変更を適用して保存する |
| `LyricsApplicationService` | `ILyricsProvider` と `IEventBus` を連携し、楽曲ごとの非同期歌詞取得（`LoadForTrackAsync`、LRU メモリキャッシュ・`forceReload`・非同期キャンセル対応）およびキャッシュ破棄・更新通知（`InvalidateCache` / `InvalidateCacheAsync` / `LyricsUpdated` イベント・`LyricsUpdatedEvent` 発行）を担う |
| `LrcGenerationApplicationService` | `IAudioAlignmentEngine`・`ITextEncodingService`・`ILocalSpeechModelManager`・`ILrcParser`・`LyricsApplicationService` を連携し、入力テキスト事前検査（`InspectLyricsTextAsync`）、テキスト強制アライメント生成（`GenerateLrcAsync`、非 UTF-8 未承諾拒否）、音声直接文字起こし生成（`TranscribeAudioToLrcAsync`）、既存 `.lrc` 読み込み（`LoadExistingLrcAsync`）、モデル管理、および `.lrc` 保存後のキャッシュ即時更新通知（`SaveLrcAsync`）を担う |
| `ListeningStatsApplicationService` | `IAudioService.TrackPlaybackEnded` を購読して `IListeningStatsRepository` へ累計再生回数・累計再生時間・`LastPlayedAt` および日時毎再生履歴（`TrackPlayEvent`）を記録・永続化し、`StatsUpdated` 通知・対象楽曲統計取得（`GetTrackStat`）・よく聴く曲 TOP N 取得（`GetTopPlayedTracks`）・全体スナップショット取得を担う（`IDisposable` 準拠） |

### 3.2 Common (`AudioEffector.Application.Common`)
- **`IEventBus` / `InMemoryEventBus`**: ドメインイベントの非同期Pub/Sub通信を提供するスレッドセーフなインメモリイベントバス。
- **`IHandle<TEvent>`**: ドメインイベントの購読ハンドラー契約。
- **`IAudioEngine`**: 低レベル音声再生エンジンの抽象インターフェース。
- **`IMetadataExtractor`**: 音声ファイルからのメタデータおよび埋め込みカバーアートバイト列抽出の抽象インターフェース（具象実装は Infrastructure 層の `TagLibMetadataExtractor`）。
- **`IUiDispatcher` / `ImmediateUiDispatcher`**: UI スレッドへの処理ディスパッチ抽象契約と、ヘッドレス・MCP・テスト環境向けの既定実装（`Invoke` は同期直接実行、`BeginInvoke` は `Task.Run` による非ブロッキング実行）。WPF 実行時は Presentation 層の `WpfUiDispatcher` で上書きされる。
- **`IDataDirectoryProvider` / `DataDirectoryProvider`**: 永続化 JSON ファイル群の格納先ディレクトリ解決契約と標準実装（未指定時は `%APPDATA%\AudioEffector`、`--data-dir` 等によるカスタム指定時は正規化パスを返却）。
- **`IJsonFileLockHelper` / `FileMetadataSnapshot` / `FileLockTimeoutException`**: プロセス間 OS ファイルロック（`.lock`）・一意一時ファイルによる原子的書き込み・更新メタデータ比較の抽象契約とタイムアウト例外型（具象実装は Infrastructure 層の `JsonFileLockHelper`）。
- **`LogDescriptionAttribute`**: `IAudioService` / `ISettingsService` 等のメソッドに付与するログ出力用説明属性（Infrastructure 層の `LoggingProxy` から参照）。
- **`LrcTransferOptions` / `CompanionLrcResolver`**: 機器転送時の種別別 `.lrc` 同梱設定（`ManualOrExternal` / `AutoGeneratedTextAlignment` / `AutoGeneratedAudioTranscription`）の評価と、音声ファイル同階層・同名 `.lrc` の先頭安全読み込み（最大 64 KB 上限・BOM 自動検出）・種別判定共通ヘルパー。
- **`Result` / `Result<T>`**: 例外スローに頼らず業務エラー（対象トラック不在、バリデーション失敗等）を呼び出し元へ型安全に伝達する結果オブジェクト。

## 4. DI（依存性注入）登録仕様

アプリケーション層のサービスは [`AudioEffector.Application/DependencyInjection.cs`](../../../AudioEffector.Application/DependencyInjection.cs) の `AddApplicationServices()` にて一括登録します。

- `IEventBus`（実装: `InMemoryEventBus`）はアプリケーション全体のイベントハブとして **Singleton** で登録します。
- 各 `ApplicationService`（`Audio`, `Library`, `Playlist`, `Equalizer`, `DataTransfer`, `Settings`, `Lyrics`, `LrcGeneration`）、`LyricsForcedAligner` および `ISettingsService` も、内部状態や設定キャッシュの一貫性を保つためすべて **Singleton** として登録します。
