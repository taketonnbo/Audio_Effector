# MCPサーバ機能仕様書

## 1. 機能概要

本機能は、Audio Effector の楽曲ライブラリ管理・プレイリスト操作・イコライザー設定・アプリケーション設定・再生制御などの機能を、標準プロトコルである **MCP (Model Context Protocol)** を通じて外部の AI エージェントや MCP クライアント（Claude Desktop、VS Code、Antigravity 等）へ公開するための「MCP サーバ機能」です。

ユーザーは、普段利用している AI アシスタントに対して自然言語で指示を出すことで、「特定のジャンルやアーティストの楽曲をライブラリから検索する」「気分に合わせたプレイリストを自動作成する」「条件に合う曲を再生する」といった高度な連携体験を得ることができます。

本機能は以下のフェーズ構成で段階的に提供します。

| フェーズ | 提供内容 | 対応 Issue |
| :--- | :--- | :--- |
| **Phase 0（本設計）** | 要件定義・アーキテクチャ設計・共通規約の策定、および前提となる非 UI 層の依存分離 | #295, #298, #303 |
| **Phase 1（基盤構築）** | `stdio` トランスポート対応の MCP サーバ実行基盤と、接続確認用の最小ツール提供 | #296 |
| **Phase 2（機能拡張）** | 楽曲検索・再生制御・プレイリスト管理・イコライザー・設定参照などの MCP Tools / Resources を順次追加 | #301, #305, #306 等 |
| **Phase 3（HTTP 対応）** | 常駐型・Web/ローカル連携向けの HTTP（Streamable HTTP）トランスポート対応 | 将来起票予定 |

## 2. ユーザー向け提供機能

### 2.1 対応トランスポートと接続方式

- **ローカル標準接続（`stdio` トランスポート / Phase 1 先行提供）**:
  - MCP クライアントの設定ファイルに Audio Effector の MCP サーバ実行ファイルを登録するだけで、クライアントの起動に合わせて自動的に MCP サーバが立ち上がり、標準入出力を通じて安全に通信できます。
  - ポート番号の管理やネットワーク設定が不要なため、ローカル PC 上の AI ツールから手軽に利用開始できます。
- **将来的なネットワーク接続（`HTTP` トランスポート / Phase 3 予定）**:
  - 将来的に起動オプションを切り替えるだけで、HTTP（Streamable HTTP）経由の接続にも対応できる設計としています。
  - HTTP 利用時も、既定ではローカル PC 内（`127.0.0.1`）からの接続のみを受け付け、外部からの意図しないアクセスを防止します。

### 2.2 疎通確認・サーバ情報取得機能（Phase 1 提供）

MCP クライアントとの接続設定が正しく完了しているかを確認するため、Phase 1 では以下の基本ツールを提供します。

- **接続確認（`ping`）**:
  - MCP サーバが正常に応答できる状態かを即座に確認できます。任意メッセージのエコー応答に加え、サーバ名・バージョン・通信方式・現在時刻（UTC）が返却されます。
- **サーバ状態取得（`get_server_info`）**:
  - MCP サーバの稼働状態、参照しているデータフォルダ、ライブラリに登録されている楽曲件数、および Audio Effector デスクトップアプリ本体との連携状態を確認できます。

### 2.3 楽曲ライブラリ・プレイリスト検索機能（Phase 2 #305, #331 提供）

AI エージェントが Audio Effector の楽曲ライブラリやユーザー作成プレイリストから目的の楽曲・アルバム・プレイリストを探し出し、メタデータや再生対象となる ID・収録曲構成を取得するための検索ツールを提供します。

- **曲の検索（`search_tracks` / #305）**:
  - キーワード（タイトル・アーティスト・アルバムを対象とした大文字・小文字区別なしの部分一致）に加え、アーティスト・アルバム・ジャンル・お気に入り登録済みのみ、といった複合条件で楽曲を絞り込めます。
  - 検索結果は `limit`（既定 50 件・上限 200 件）および `offset`（既定 0）によるページネーションに対応しており、総件数（`totalCount`）と今回返却件数（`count`）を合わせて取得できます。
  - Audio Effector デスクトップアプリ本体が未起動の状態でも利用でき、デスクトップアプリ側で更新された最新のライブラリおよびお気に入り状態が再起動なしで反映されます。
  - **利用例**:
    - 「タイトルやアーティストに `Jazz` を含むお気に入りの曲を 10 件探して」
    - 「アルバム名に `Best` を含むロックジャンルの楽曲一覧を取得して」
- **アルバムの検索（`search_albums` / #331）**:
  - キーワード（アルバム名・アーティスト名を対象とした大文字・小文字区別なしの部分一致）に加え、アーティスト・収録楽曲ジャンル・リリース年でアルバム一覧を絞り込めます。
  - 各アルバムについて、決定論的な `id`（`AlbumId`）・アルバム名・アーティスト名・代表リリース年・収録曲数・総再生時間・ハイレゾ／ロスレス有無を返却し、`includeTracks: true` を指定すると収録トラック一覧も合わせて取得できます。
  - Audio Effector デスクトップアプリ本体が未起動の状態でも利用でき、後続のアルバム再生ツールへそのまま渡せる識別情報を取得できます。
  - **利用例**:
    - 「2024 年リリースのジャズ系アルバムを一覧で教えて」
    - 「アーティスト `Miles Trio` のアルバムと収録曲を確認して」
- **プレイリストの検索（`search_playlists` / #331）**:
  - キーワード（プレイリスト名を対象とした大文字・小文字区別なしの部分一致）およびページネーションでユーザー作成プレイリスト一覧を検索できます。
  - 各プレイリストについて `id`（GUID）・プレイリスト名・収録曲数・作成日時・更新日時を返却し、`includeTracks: true` を指定すると収録トラック一覧も順序通りに取得できます。
  - Audio Effector デスクトップアプリ本体が未起動の状態でも利用でき、デスクトップアプリ側で更新された最新プレイリストが再起動なしで反映されます。
  - **利用例**:
    - 「名前に `Drive` を含むプレイリストと収録曲を教えて」
    - 「作成済みのプレイリスト一覧をすべて表示して」

### 2.4 アプリ起動機能（Phase 2 #316 提供）

再生制御系ツール（#306 等）を利用する前提として、AI エージェントが Audio Effector デスクトップアプリ本体を柔軟な起動モードで立ち上げるための起動ツールを提供します。

- **アプリの起動（`launch_app`）**:
  - 起動モード（`mode`）として **`mini_player`（既定値・ミニプレイヤー起動）** または **`normal`（通常ウィンドウ起動、`StartMinimized` 設定が有効でも初回は通常画面で表示）** を指定して Audio Effector 本体を起動できます。
  - 起動後、WPF 本体の Named Pipe IPC 待受が準備完了になるまで待機するかどうかを `waitForReady`（既定値: `true`）で制御できます。
  - Audio Effector 本体がすでに起動済みの場合は、多重起動を行わず、**現在のウィンドウ状態（メイン画面／ミニプレイヤー）をそのまま維持したうえで** `alreadyRunning: true` として正常応答を返します。
  - MCP クライアントや MCP サーバが終了した後も、起動された Audio Effector 本体（およびミニプレイヤー）は独立プロセスとして動作を継続します。
  - **利用例**:
    - 「Audio Effector をミニプレイヤーで起動して」
    - 「Audio Effector を通常画面で起動して」

### 2.5 楽曲・アルバム・プレイリスト再生・基本再生制御および再生状態取得機能（Phase 2 #306, #328, #329, #330 提供）

AI エージェントが「曲の検索」（#305: `search_tracks`）や「アルバム・プレイリストの検索」（#331: `search_albums`, `search_playlists`）等で特定した楽曲・アルバム・プレイリストを、起動中の Audio Effector デスクトップアプリ本体で即座に再生開始したり、現在の再生状況の照会や一時停止・再開・停止・次曲・前曲といった基本トランスポート操作を行うための再生系ツールを提供します。

- **再生状態の取得（`get_playback_state` / #328）**:
  - 起動中の Audio Effector デスクトップアプリ本体の現在の再生状態（`playing` / `paused` / `stopped`）、再生中または一時停止中のトラック情報、現在の再生位置・総再生時間、音量（`0.0`〜`1.0`）、シャッフル／リピート状態、および予約キュー・アルバム残り曲キューの件数を読み取り専用で取得できます。
  - 停止中・トラック未選択時もエラーとせず、`playbackState: "stopped"`・`track: null` の正常応答を返却します。
  - 本ツールの呼び出しによって、WPF 本体の再生状態・再生位置・ウィンドウ状態（通常メイン画面／ミニプレイヤー）に一切の副作用は生じません。
  - **利用例**:
    - 「今 Audio Effector で何の曲を再生しているか教えて」
    - 「現在の音量とシャッフル・リピート設定、キューに残っている曲数を確認して」

- **基本再生制御（トランスポート操作 / #329）**:
  - 起動中の Audio Effector デスクトップアプリ本体のウィンドウ状態（通常メイン画面／ミニプレイヤー）を維持したまま、画面上の再生バー・曲情報・再生キュー・ミニプレイヤー・スペクトラムアナライザ等とリアルタイムに同期して基本再生操作を実行できます。
  - **一時停止（`pause_playback`）**: 再生中の楽曲を一時停止します。すでに一時停止中の場合は状態を反転させず冪等に `paused` を返却します。完全停止中（トラック未ロード）の場合は対象トラックがない旨のエラーを返却します。
  - **再生再開（`resume_playback`）**: 一時停止中の楽曲を再開（待機中トラックやキューがある場合は再生開始）します。すでに再生中の場合は冪等に `playing` を返却します。再開対象のトラック・キューが存在しない場合は `play_track` 等での再生開始案内付きエラーを返却します。
  - **停止（`stop_playback`）**: 再生中・一時停止中の再生を停止して `stopped`（`track: null`）を返却します。すでに停止中の場合も冪等に `stopped` を返却します。
  - **次の曲（`next_track`）**: 予約キュー・アルバム残り曲キューの次の曲（またはリピート有効時は先頭曲）へ移動し、遷移後の再生状態と新トラック情報を返却します。次曲が存在せず末尾に到達した場合は停止状態（`stopped` / `track: null`）を返却します。
  - **前の曲（`previous_track`）**: 現在の再生位置が 3 秒超の場合は現在曲の先頭へ戻り、3 秒以内の場合は現在曲の先頭から再再生（先頭曲かつリピート有効時は末尾曲へ循環）します。完全停止中（トラック未選択）の場合は対象トラックがない旨のエラーを返却します。
  - **利用例**:
    - 「今流れている曲を一時停止して」
    - 「一時停止していた曲を再開して」
    - 「次の曲にスキップして」
    - 「この曲の頭に戻して（前の曲に戻って）」
    - 「再生を停止して」

- **曲の再生（`play_track` / #306）**:
  - 再生対象として **`trackId`（トラックの GUID）** または **`filePath`（音声ファイルの絶対パス）** のいずれか（少なくとも一方必須、両方指定時は `trackId` 優先）を指定して再生を開始できます。
  - Audio Effector デスクトップアプリ本体が起動済みの場合、**現在のウィンドウ状態（通常メイン画面／ミニプレイヤー）を変更せず維持したまま**、再生バー・再生中曲情報・再生キュー・ミニプレイヤー・スペクトラムアナライザ等の画面表示をリアルタイムに完全同期させて再生を開始します。
- **アルバムの再生（`play_album` / #330）**:
  - **`albumId`（決定論的 `AlbumId` の GUID）** または **`albumName`（大文字・小文字区別なし、必要に応じて `artist` で同名アルバムを絞り込み）** を指定して、アルバム全体の再生および残り曲のキュー展開を開始できます。
  - 途中曲から開始したい場合は `startTrackId` または 0 始まりの `startTrackIndex`（`startTrackId` 優先）を指定できます。
  - `shuffle`（シャッフル再生）・`repeat`（リピート再生）を任意指定でき、省略時は Audio Effector 本体の現在の設定を維持します。`shuffle: true` かつ開始曲未指定時はアルバム内からランダムに開始曲を選出し、残りの曲をシャッフル順でキューへ展開します。変更されたシャッフル／リピート状態は WPF 画面上のボタン表示にもリアルタイム同期されます。
  - **利用例**:
    - 「アルバム `Midnight Sessions` をシャッフル＆リピートで流して」
    - 「`search_albums` で見つけたアルバムの 3 曲目から再生して」
- **プレイリストの再生（`play_playlist` / #330）**:
  - **`playlistId`（GUID）** または **`playlistName`（大文字・小文字区別なし）** を指定して、ユーザー作成プレイリストの収録順（またはシャッフル順）での再生およびキュー展開を開始できます。
  - `startTrackId` / `startTrackIndex` による途中曲開始、および `shuffle` / `repeat` の切り替えに対応し、欠損した音声ファイルは自動的にスキップして再生可能な楽曲のみで連続再生します。
  - **利用例**:
    - 「ドライブ用プレイリストをシャッフル再生して」
    - 「`search_playlists` で取得したプレイリストを最初からリピート再生して」
- **未起動時の振る舞い（共通）**:
  - Audio Effector デスクトップアプリ本体が未起動の状態で呼び出した場合は、意図しないバックグラウンド再生や多重起動を行わず、エラーコード `WPF_APP_NOT_RUNNING` とともに **`launch_app` ツールでの事前起動を案内するメッセージ** を返却します。
  - **利用例（検索 / `launch_app` との連携フロー）**:
    1. 「Jazz のお気に入りの曲やアルバムを探して」（`search_tracks` / `search_albums` / `search_playlists` で ID を取得）
    2. 「Audio Effector をミニプレイヤーで起動して」（未起動時のみ `launch_app(mode: "mini_player")`）
    3. 「そのアルバムをシャッフルで再生して」（`play_album(albumId: "...", shuffle: true)`）

### 2.7 Audio Effector デスクトップアプリ本体との共存動作

- **最新ライブラリ・設定の共有**:
  - Audio Effector デスクトップアプリ本体と MCP サーバは、同じユーザーデータ領域（`%APPDATA%\AudioEffector\`）を参照します。
  - デスクトップアプリ側で新しく楽曲フォルダをスキャンしたりプレイリストを編集した場合でも、MCP サーバを再起動せずに最新のデータへアクセスできます。
  - 双方から同時にデータへアクセスしても、ファイルが破損しないよう安全な排他制御が行われます。
- **再生操作時の振る舞い**:
  - 楽曲の検索やプレイリスト・設定の確認は、Audio Effector デスクトップアプリ本体を起動していない状態でも利用できます。
  - 再生開始や一時停止などのリアルタイム再生操作は、起動中の Audio Effector デスクトップアプリ本体と連携して実行されるため、アプリ画面上の再生バー・ミニプレイヤー・スペクトラムアナライザ・再生キューと完全に同期します。
  - デスクトップアプリ本体が起動していない状態で再生操作を実行した場合は、意図しないバックグラウンド再生を防ぐため、「Audio Effector 本体を起動してから再試行してください」といった分かりやすい案内メッセージを返します。

### 2.8 分かりやすいエラー通知と安全なログ出力

- **一貫したエラー案内**:
  - 指定したパラメータに誤りがある場合、対象の楽曲やファイルが見つからない場合、あるいはデスクトップアプリ本体が未起動の場合などに、原因と対処法が分かる構造化エラーメッセージを返却します。
  - これにより、AI エージェントが状況を正確に判断し、ユーザーへ適切な提案やリトライを行えます。
- **通信を妨げない診断ログ**:
  - 動作状況やトラブル調査用のログは、MCP の通信経路を妨げない専用の出力先（標準エラー出力および MCP サーバ専用ログファイル）へ記録されます。

## 3. 利用手順（想定ワークフロー）

1. **MCP クライアントへの登録**:
   - 利用する MCP クライアント（Claude Desktop、VS Code、Antigravity 等）の設定ファイルに、Audio Effector MCP サーバの起動コマンドを登録します。
   - 設定イメージ（`stdio` モード）：
     ```json
     {
       "mcpServers": {
         "audio-effector": {
           "command": "C:\\Path\\To\\AudioEffector.McpServer.exe",
           "args": ["--transport", "stdio"]
         }
       }
     }
     ```
2. **接続と疎通確認**:
   - MCP クライアントを起動（または設定を再読み込み）し、AI アシスタントへ「Audio Effector MCP サーバの疎通確認をして」と依頼します。
   - `ping` / `get_server_info` が成功し、バージョンや登録トラック数が返却されることを確認します。
3. **自然言語でのライブラリ活用・操作（Phase 2 以降）**:
   - 例：「ロックジャンルの曲を検索して」「お気に入りの曲からドライブ向けプレイリストを作って」「この曲を再生して」のように自然言語で指示を出します。
   - 再生操作を行う場合は、あらかじめ Audio Effector デスクトップアプリ本体を起動しておきます。
4. **利用終了**:
   - MCP クライアントを終了すると、MCP サーバプロセスも自動的に安全な終了処理（リソース解放）を行って終了します。
